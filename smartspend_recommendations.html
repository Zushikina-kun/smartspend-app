Based on a full read of DOCUMENTATION.md and the context file. These are recommendations beyond the existing pending list — grouped by what kind of work they are. Effort dots: low   medium   high.
🗄 Untapped data — fields already in DB, zero display Quick wins
UD-1Time-of-day spending heatmap
You already store expenses.time on every entry. A second heatmap alongside the day-of-week one — but by hour (7AM–11PM) — would surface "you spend most between 12–2PM" instantly. Same visual pattern as the existing heatmap, just a different axis. Data's already there; zero new columns needed.
Low — reuse heatmap widget logic, new data query
UD-2Payment method analytics breakdown
expenses.payment_method is stored and shown per tile but never aggregated. A simple pie or bar chart in Analytics — Cash vs GCash vs Card — would immediately answer "am I spending more digitally or physically?" Also useful for defense: demonstrates you're using all the data you collect.
Low — one new chart, existing data
UD-3Top merchants card + merchant-based auto-rule suggestions
expenses.shop_name is stored on every AI-logged entry. Surface the top 5 merchants this month ("You've been to Jollibee 12×, ₱1,740 total"). Bonus: when a merchant appears 3+ times without a category rule, prompt: "You log Jollibee often — add a rule to auto-categorize it?" This closes the loop between the new category_rules system and actual usage patterns.
Low — query + card + optional rule prompt
UD-4Confidence score feedback loop
expenses.confidence_score is stored and shown as an orange dot, but that's where it stops. Two ideas: (1) a "low confidence" filter chip in Transactions (already on the pending list as CF-1); (2) actually use corrections as training signal — when a user edits an AI-parsed entry's category, that correction should automatically create/update a category_rule. The correction IS the feedback. Right now corrections are thrown away.
Low for filter chip / Medium for auto-rule-from-correction
UD-5Income category breakdown chart
income.category is stored (Salary, Allowance, Freelance, Gift, etc.) but the income screen is just a list. Add a simple pie showing income by source. For students this shows "Allowance 80%, Freelance 20%." For freelancers it shows which client categories are dominant. Very relevant for defense since it demonstrates multi-source income tracking.
Low — one new chart on the income screen
UD-6Scan history linked to expenses
scan_history records every barcode scan but is completely disconnected from expenses. When showing a scan in history, check if an expense with matching shop_name or item_name exists on the same date. If so, show a "linked to [expense]" indicator. Bonus: if a barcode was scanned but no expense was logged, show "Unlogged scan — add expense?" nudge.
Medium — requires join/matching logic
UD-7mood_log.note field — currently unused
The mood_log table has a note TEXT column that's never exposed. When the user taps a mood emoji, show an optional one-line "what's going on?" text field. Even 20% of users filling this in makes the mood-spend correlation card much richer. The AI context could also include today's mood note, so the AI can respond empathetically: "I see you're feeling a bit off today — let's keep spending minimal."
Low — one text field on existing mood check-in
UD-8Debt interest_rate — show real cost projection
debts.interest_rate is stored but not displayed anywhere. Show "At ₱500/month, you'll pay approx. ₱X in total interest" using the stored rate. Even a simple formula without amortization math would be more useful than showing nothing. Already on the pending list as DT-1 but worth flagging it's truly zero-effort on the data side — just math and display.
Low — pure display/math, data already there
UD-9Installment remaining balance + total interest paid
The installments table has months_total, months_paid, interest_rate, and start_date. Currently the screen only shows a progress bar. With those fields you can calculate: remaining balance, total amount paid so far, total interest you'll pay at current rate, and projected payoff date. A one-line "Payoff: March 2027" would be genuinely useful.
Low — all fields exist, just display math
🔗 Features that exist but aren't connected to each other Medium value
FC-1Mood log → AI context injection
The mood check-in runs on the home screen and stores data, but today's mood is never passed to the AI. Adding today's mood score + optional note to the AI context (AIChatService.setFullContext) costs almost nothing — it's one DB read. The AI could then proactively adjust tone: if mood is 1–2, avoid suggestions that feel like lectures; if mood is 5, it's a good time to suggest goal contributions. Right now the mood system is an analytics island.
Low — one extra field in the context object
FC-2Score history → Bill Calendar dots
score_history is already populated daily and used for the line chart. The Bill Calendar is a monthly calendar that currently only shows recurring bill due dates. Adding small score dots (color-coded: green/yellow/red) on each day would turn it into a proper financial journal view — you can see at a glance: "my score dropped on the 15th because that's when I overspent on food." Already on the pending list as SC-1, but it's more impactful than it looks — it's the only way to see score + behavior + bills in one timeline. Strong defense talking point.
Medium — requires calendar widget modification
FC-3Want/Need tagging → AI uses it during logging
expenses.is_want exists and feeds the 50/30/20 tracker and Wants vs Needs chart, but the AI never sets this field when logging. When the AI calls log_expense, it already infers category — it can equally infer need vs want from category (Food = Need, Shopping = Want, Entertainment = Want). Add is_want inference to the ACTION JSON so AI-logged expenses are tagged from day one. Right now 100% of AI-logged entries default to Need=0 which makes the 50/30/20 tracker inaccurate. Already in pending as CF-2 — but the impact is bigger than "nice to have."
Low — add one field to AI action parser output
FC-4Notes field → AI context + Transactions search
expenses.notes is stored and displayed in tiles but: (1) not included in Transactions search, and (2) not passed to the AI. Both are in the pending list (NT-1, NT-2) but worth flagging together because they're the same fix — adding notes to the data pipeline. Particularly useful for AI: a user who writes "birthday dinner" in notes gets better advice than one whose entry just says "Food ₱850."
Low — search index extension + one context field
FC-5Windfall flag → FHS and forecast actually use it
The income.is_windfall column was just added this version and the docs say "AI and forecasts can treat it differently" — but does the code actually do this yet? Worth verifying that PredictService.predictLongRange() and the FHS savings rate component genuinely exclude windfall income from baseline calculations. If a student got a ₱5,000 birthday gift and logs it, it shouldn't make their 3-month forecast look artificially good or inflate their savings rate score.
Low — a conditional filter in existing service methods
FC-6Category rules → show match count + last triggered
The ManageRulesScreen shows a list of keyword → category rules but has no feedback on whether they're working. Add a match count ("triggered 8 times") and last matched date to each rule. Users with rules that never trigger probably misspelled the keyword. This also makes for a great defense demo — "the system learns from user corrections and you can see exactly how often each rule fires."
Low — add two columns to category_rules or compute from expenses
⚙️ Behavior tweaks — existing features not working to full potential Tweaks
BT-1Quick-log chips should show spend trend, not just the name
The home screen quick-log chips show top 4 most frequent expenses as one-tap chips. Currently they just show item name + amount. Consider adding a tiny indicator: "↑ ₱20 more than usual" or "same as always." This turns a shortcut into a micro-insight. The data for this is already there — you have the expense history to compute a rolling average per item.
Low — average query per chip item
BT-2FHS warning decay is silent — make it visible
The warning decay system (−5pts/day for up to 3 days when budget is exceeded) fires notifications but there's no visual on the score card itself showing "you're in a decay period." If a user misses the notification, they see their score drop with no explanation. Show a small amber indicator on the FHS card: "Score reduced — budget exceeded for 2 consecutive days." This makes the decay system feel fair rather than mysterious.
Low — read warning_decay_days setting, show conditional badge
BT-350/30/20 tracker always shows this month — add period awareness
The docs explicitly note: "50/30/20 Rule Tracker always uses this-month data regardless of period filter." This is the only analytics card that ignores the period filter. For consistency and for users who want to check a past month's 50/30/20 split, it should respect the selected period. It's a surprising exception that could confuse reviewers during defense ("why is this chart not updating when I change the period?").
Medium — wire period filter into the 50/30/20 query
BT-4AI daily limit counter — show when it resets, not just how many remain
The AI screen shows the remaining message count in the appbar. When count hits 0, users know they're blocked but not for how long. Add a small note under the limit: "Resets at midnight" or a countdown like "Resets in 4h 22m." Small UX fix but removes a point of confusion that could hurt demo impressions.
Low — time math from current time to midnight
BT-5Recurring → Log Now doesn't pre-fill amount for editing
The docs mention "Log Now button records expense as expense entry" — but the v2.5 context file lists "Log Now lets user adjust amount before confirming" as a feature in the brainstorm backlog, implying it might not be fully implemented. If Log Now still logs the fixed amount immediately without an edit step, it should be updated. Variable recurring expenses (electricity, water) are common and users will have wrong amounts logged silently.
Low — intercept Log Now with a bottom sheet showing editable amount
BT-6Anomaly detection fires on Sunday only — consider on-open trigger
Anomaly detection (2.5× above 4-week category average) only runs on Sundays. If someone makes a massive one-off purchase on a Monday, they won't be alerted until the following Sunday — by then it's no longer relevant. Consider adding an on-expense-log trigger: after each AI expense log, quietly check if the new entry is an anomaly in its category. Fire immediately if it is. The Sunday batch can remain for patterns, but point anomalies deserve real-time detection.
Medium — add post-log check in AIChatService action handler
💡 New ideas — not on any existing list New additions
NI-1"Where did my money go?" AI quick-answer card on Home
A persistent home card that, without any user input, surfaces a 1-sentence AI-generated summary of this month's biggest money movements. "You've spent 40% of this month's budget on Food, mostly in the first week." Cached like the existing insight card, regenerates when expense count changes. The key difference from the existing AI insights: it's answering a specific question, not general advice. Lower cognitive load for users who just want the punchline.
Low — reuse existing insight infrastructure, new focused prompt
NI-2Goal contribution progress relative to deadline
Goals show current amount vs target and a days-left countdown, but they don't tell you if you're on pace. Add a pace indicator: "You need ₱X/month to reach this by [deadline]. You're currently ₱Y/month ahead/behind." This uses start_date, deadline, target_amount, and current_amount — all already stored. Turns a static progress bar into an actionable status. Particularly useful for capstone defense since it demonstrates deadline-aware financial planning.
Low — math on existing fields, one line of UI
NI-3AI "did you mean to log this?" duplicate detector
If the AI receives a log request for an item that's very similar to something logged in the last 2 hours (same category, similar amount, same shop), prompt: "You already logged Jollibee ₱149 at 1:03PM — is this a duplicate?" before writing. The existing duplicate blocking only handles exact same-second timestamps from batch AI logs, not genuine accidental double-logging by users. A fuzzy same-day same-item check would prevent a real pain point.
Medium — fuzzy match query before INSERT in action handler
NI-4quiz_challenge setting — currently collected but never used
The settings table stores quiz_challenge from onboarding (values: debt / overspending / saving / tracking). This is the user's declared #1 financial challenge — but it's never referenced anywhere after setup. This should influence: which home cards are shown first, what the AI emphasizes in advice, which analytics sections are highlighted. A user who said "debt" should see the debt screen more prominently than one who said "tracking."
Medium — read setting in home/analytics/AI context, adjust ordering or emphasis
NI-5Net worth trend over time, not just today's number
The Profile screen shows a Net Worth card (assets − liabilities) as a point-in-time number. You have score_history for daily scores — consider also snapshotting net worth daily (or weekly) and showing a simple sparkline on the Net Worth card: "up ₱1,200 this month." Net worth growing over time is one of the most motivating financial metrics. The snapshot could be computed and stored in a new table, or approximated from income/expense history.
Medium — new daily snapshot + sparkline widget
NI-6One-tap "I'm done spending for today" mode
A simple toggle — possibly in the home screen quick actions or the daily limit card — that lets users voluntarily declare "I'm done spending today." Triggers a push notification if any new expense is logged after this point ("You said you were done for today — still want to log this?"). Builds self-commitment, which behavioral research consistently shows is more effective than external restrictions. Very low effort, very high behavioral value, and a unique feature that would stand out in the defense.
Low — one SharedPreferences bool + notification hook
NI-7Recurring income auto-log suggestion
When a recurring item marked is_expense = 0 (income recurring) is due, the app currently handles it the same as expense recurring. But income recurring should be treated differently: instead of just a Log Now chip, show a more prominent "Your allowance is due today — log it?" card on the home screen. This also feeds into the cash flow card and FHS savings rate. Many students forget to log their weekly allowance, which makes their income appear lower than it is.
Low — filter is_expense=0 from recurring and give it special home card treatment
🎓 Capstone defense value — highest ROI for remaining time Priority
The items with the best effort-to-impression ratio for defense, in order:

1. FC-3 (is_want AI tagging) — makes 50/30/20 actually accurate. Reviewers will ask "how does this work?" and right now the answer has a gap.

2. NI-4 (quiz_challenge used) — "the app personalizes based on your declared challenge" is a strong thesis point that's currently a dead setting.

3. FC-1 (mood → AI context) — "the AI knows your mood and adjusts its tone" is a compelling demo moment that takes one DB read to implement.

4. UD-3 (top merchants + rule suggestion) — closes the loop on the auto-categorization rules feature. Right now rules are manual; this makes them feel intelligent.

5. NI-2 (goal pace indicator) — turns a progress bar into a financial advisor. One calculated line, huge perceived value.
