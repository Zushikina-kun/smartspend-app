FHS Score Adjustments (for panelist questions):
• Warning Decay: up to −15 pts for discretionary overspend (loss aversion principle)
• Gap Adjustment: +2/day confirmed no-spend, −3/day unlogged-but-presumed-spent
• Final score clamped 0–100
• Lightweight Mode for users without fixed income: Spending Restraint + Logging Consistency + Category Balance + Habit Streak

SmartSpend  |  LORMA Colleges, CCSE
Privacy by design: three AI tiers
1
Cloud AI (default)
On-device redaction of mobile numbers, reference numbers, and account patterns. 150 AI requests per user per day. Disclosure shown before the first AI message.
Implemented
2
Private Local Mode
Requests go only to a model on the user's own PC (Ollama, LM Studio, Jan). Local-only switch blocks cloud fallback.
Implemented
3
On-device AI
A model running on the phone itself, with no network required. NOT yet built — presented as Recommendation 4. Most target-user devices lack the RAM to run a 2.6 GB model.
Planned
Designed with the Data Privacy Act of 2012 in mind. A risk-reduction measure, not a certification of legal compliance.

Limitations we acknowledge
Usability below target
SUS 61.83 is under the 68 avg. benchmark (Sauro & Lewis 2016) and the 80 target.
Android and internet
Android only; all AI features need a connection.
Prototype-grade security
API key via Remote Config; local database not encrypted.
Parsing accuracy
91.2% precision / 88.5% recall from developer testing.
Behavior impact unmeasured
Peso and badges were added after the evaluation was designed.
Small, local sample
30 SUS respondents from one locale; not generalizable.
