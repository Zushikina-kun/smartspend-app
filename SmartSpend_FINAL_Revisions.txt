"Flutter. Flutter is an open-source UI framework developed by Google, used to
build the SmartSpend Android application. It provides a rich set of widgets
and tools that enable the development of a responsive, visually consistent,
and feature-rich mobile interface (Google, 2024).

SQLite (sqflite). The application uses SQLite as its primary local database
(version 10), storing all financial data — including expenses, budgets,
savings goals, income, recurring transactions, debts, and chat history —
directly on the device. This ensures full offline functionality without
requiring an internet connection (Rahman, 2022).

Firebase Firestore. Firebase Firestore is used for bidirectional cloud
synchronization of user financial data. Every write operation is automatically
pushed to Firestore, and on login, the application pulls cloud data and merges
it into the local database, enabling seamless multi-device access to the same
financial records (Google, 2023).

Firebase Authentication. Firebase Authentication handles user identity
management, supporting email/password login, Google Sign-In via OAuth 2.0,
and biometric authentication (fingerprint or face unlock) as a convenience
layer after the user's first successful login (Google, 2023).

Firebase Crashlytics. Firebase Crashlytics is integrated for real-time crash
reporting, capturing Flutter framework errors and asynchronous exceptions and
reporting them to the Firebase Console for monitoring and debugging.

Groq API (LLaMA 3.1 8B Instant). The system uses the Groq API with the
LLaMA 3.1 8B Instant model as its AI engine. This model handles three tasks:
(1) parsing natural language expense descriptions into structured JSON data,
(2) generating spending insights and financial advice, and (3) powering the
conversational AI assistant that can execute real-time data actions from chat
(Groq, 2024).

Speech-to-Text. The speech_to_text package is used to implement voice input
for expense recording. The system auto-detects Filipino English (en_PH) locale
with a fallback to en_US, supporting a 15-second listening window with
automatic pause detection (Google, 2024).

Google ML Kit Text Recognition (OCR). Google ML Kit's Latin script text
recognizer is used to extract text from receipt photos. The extracted text is
cleaned, trimmed, and passed to the AI parser for structured data extraction.
Users may capture a new photo or select from the gallery (Google, 2024).

Mobile Scanner (Barcode). The mobile_scanner package is used for barcode
scanning. Each scan is saved to a local scan history, and a dialog prompts
the user to describe the product before AI parsing. The scanner includes a
torch toggle and visual overlay guide frame (ZXing, 2023).

Google Drive REST API. The application uses the Google Drive REST API with
the appDataFolder scope to implement backup and restore functionality. All
financial data is exported as a JSON file to the user's private Drive storage,
invisible to the user's regular Drive files (Google, 2024).

fl_chart. The fl_chart package is used to render interactive charts in the
Analytics screen, including a pie chart for category breakdown, a bar chart
for monthly spending trends, and a line chart for the 30-day Financial Health
Score history.

local_auth. The local_auth package enables biometric authentication
(fingerprint or face unlock) as a login option after the user's first
successful login, using the device's enrolled biometrics with PIN fallback."

"APPENDIX E
Additional Technical Documentation

This section presents additional technical details of the SmartSpend system,
including its architecture, data flow, input-process-output structure, tools
and technologies, and development methodology.

1. System Architecture Overview

The SmartSpend system consists of the following integrated components:

   a. Mobile Application (Flutter — Android)
      User interface layer with 22+ screens, state management via setState
      and AppEventBus (global event bus for real-time UI refresh), edge-to-edge
      UI with five customizable color themes and dark mode support.

   b. Local Database (SQLite — version 10)
      Eleven tables: expenses, budgets, savings_goals, income, recurring,
      debts, chat_history, user_profile, settings, score_history, and
      scan_history. Automatic column migration ensures compatibility across
      app updates.

   c. Cloud Sync (Firebase Firestore — Spark plan)
      Bidirectional synchronization: every write operation pushes to Firestore;
      on login, the application pulls cloud data and merges it into the local
      database. Synchronized collections: expenses, budgets, goals, income,
      recurring transactions, and debts.

   d. Authentication (Firebase Auth)
      Supports email/password login, Google Sign-In (OAuth 2.0), and biometric
      authentication (fingerprint/face unlock via local_auth).

   e. AI Engine (Groq API — LLaMA 3.1 8B Instant)
      Handles expense parsing (natural language to structured JSON), spending
      insights, financial advice, and conversational assistant with real-time
      action execution.

   f. OCR Module (Google ML Kit — Latin script)
      Receipt photo or gallery image to text extraction, cleaned and passed
      to AI parser.

   g. Barcode Scanner (mobile_scanner)
      Barcode scan saved to scan history; user describes product; AI parses
      description into expense data.

   h. Voice Input (speech_to_text)
      Filipino English (en_PH) or en_US locale, 15-second window, automatic
      pause detection.

   i. Backup (Google Drive REST API — appDataFolder)
      Manual backup and restore of all financial data as a JSON file stored
      in the user's private Drive folder.

   j. Crash Reporting (Firebase Crashlytics)
      Real-time tracking of Flutter framework errors and asynchronous
      exceptions, reported to Firebase Console.

2. Data Flow Process

   Step 1: User inputs data via one of four methods:
           - Manual text entry
           - Voice command (speech_to_text converts audio to text)
           - Receipt photo (ML Kit OCR extracts text)
           - Barcode scan (user describes product after scan)

   Step 2: Text input is sent to Groq API (LLaMA 3.1 8B) for parsing

   Step 3: AI returns structured JSON containing item_name, category,
           amount, date, shop_name, payment_method, and confidence_score

   Step 4: User reviews and confirms the parsed data on the Add Expense screen

   Step 5: Confirmed data is saved to local SQLite database

   Step 6: AppEventBus fires an expenseChanged event

   Step 7: All subscribed screens (Dashboard, Analytics, AI Chat) auto-refresh

   Step 8: Data is pushed to Firebase Firestore in the background

   Step 9: Financial Health Score is recalculated and saved to score_history

3. Input-Process-Output Summary

   INPUT:
   - Text input (manual description)
   - Voice input (spoken expense description)
   - Receipt images (camera or gallery)
   - Barcode scans (product identification)
   - User financial settings (income, budgets, account type)

   PROCESS:
   - AI (LLM) natural language parsing to structured data
   - OCR text extraction from receipt images
   - Financial data categorization and storage
   - Financial Health Score calculation
   - Budget compliance monitoring
   - Spending trend analysis and prediction

   OUTPUT:
   - Organized expense records (local + cloud)
   - Financial Health Score (0–100) with breakdown
   - Spending charts (pie, bar, line)
   - Budget alerts and notifications
   - AI-generated insights and recommendations
   - Monthly spending predictions
   - Tax and savings estimates (PH BIR TRAIN Law)

4. Tools and Technologies Used

   Framework:          Flutter 3.x (Dart) — Android
   AI / LLM:           Groq API — llama-3.1-8b-instant
   Local Database:     SQLite via sqflite (version 10)
   Cloud Sync:         Firebase Firestore (Spark plan — free)
   Authentication:     Firebase Auth (email + Google OAuth + biometric)
   Crash Reporting:    Firebase Crashlytics
   OCR:                Google ML Kit Text Recognition (Latin script)
   Charts:             fl_chart
   Voice Input:        speech_to_text (en_PH / en_US)
   Barcode Scanner:    mobile_scanner
   Exchange Rates:     open.er-api.com (free, no API key required)
   Backup:             Google Drive REST API (appDataFolder)
   Biometric Auth:     local_auth
   Google Sign-In:     google_sign_in
   State Management:   setState + AppEventBus (global event bus)

5. Development Methodology Summary

   The system follows the Agile Kanban Software Development Methodology,
   which includes the following stages:

   Stage 1 — Requirements: Gathering user needs through surveys and
   interviews with selected faculty respondents to identify financial
   management challenges and preferred features.

   Stage 2 — Planning: Organizing and prioritizing tasks using a Kanban
   board to ensure systematic and efficient development.

   Stage 3 — Design: Creating the system architecture, database schema,
   and user interface designs for all application screens.

   Stage 4 — Development: Implementing the system incrementally using
   Flutter, integrating AI, OCR, voice, barcode, Firebase, and all other
   components.

   Stage 5 — Testing: Verifying functionality, fixing bugs, and conducting
   usability evaluation with faculty respondents using the SUS questionnaire.

   Stage 6 — Deployment: Installing the application on Android devices
   for actual use and evaluation.

   Stage 7 — Review: Evaluating overall performance, usability, and
   effectiveness based on SUS scores, user feedback, and testing results."
